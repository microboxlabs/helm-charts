MIOT Harness has been deployed.

1. Reach the harness from your laptop:
{{- if .Values.httpRoute.enabled }}
{{- if .Values.httpRoute.hostnames }}
   export APP_HOSTNAME={{ .Values.httpRoute.hostnames | first }}
{{- else }}
   export APP_HOSTNAME=$(kubectl get --namespace {{ (first .Values.httpRoute.parentRefs).namespace | default .Release.Namespace }} gateway/{{ (first .Values.httpRoute.parentRefs).name }} -o jsonpath="{.spec.listeners[0].hostname}")
{{- end }}
   echo "Visit https://$APP_HOSTNAME"
{{- else if .Values.ingress.enabled }}
{{- range $host := .Values.ingress.hosts }}
{{- range .paths }}
   echo "Visit http{{ if $.Values.ingress.tls }}s{{ end }}://{{ $host.host }}{{ .path }}"
{{- end }}
{{- end }}
{{- else }}
   kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "miot-harness.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
   # then in another terminal:
   curl -s http://127.0.0.1:{{ .Values.service.port }}/health | jq .
{{- end }}

2. Verify the boot succeeded:

   curl -sf http://127.0.0.1:{{ .Values.service.port }}/health > /dev/null && echo OK || echo FAIL

   The harness should serve `/health` with HTTP 200 within seconds of
   the Pod going Ready. `/health` includes a `datasource` block
   (`{"name": "{{ .Values.datasource.kind }}", "enabled": ..., "tools": ...,
   "snapshot_age_minutes": ...}`). If `enabled` is `false` despite a
   configured DSN, the freshness gate likely refused a stale snapshot
   (provider default: refuse after 240 minutes; override via
   `datasource.freshnessRefuseMinutes`). See:
   https://microboxlabs.github.io/helm-charts/en/charts/modulariot/miot-harness#troubleshooting

3. Watch the boot log for datasource registration:

   kubectl logs -n {{ .Release.Namespace }} -l "app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/name={{ include "miot-harness.name" . }}" -f

   On a healthy boot you'll see the `{{ .Values.datasource.kind }}`
   provider register its tools.

{{- $tunnels := include "miot-harness.tunnels" . | fromYamlArray }}
{{- if $tunnels }}

4. Connectivity sidecars are enabled. Each reports ready only once its path is
   up, so a Pod that never reaches Ready points at a sidecar, not at the app:
{{- range $t := $tunnels }}
{{- if $t.port }}

   kubectl exec -n {{ $.Release.Namespace }} <pod> -c {{ $t.name }} -- \
     nc -z 127.0.0.1 {{ $t.port }} && echo "{{ $t.name }} up"
{{- else }}

   kubectl logs -n {{ $.Release.Namespace }} <pod> -c {{ $t.name }}
{{- end }}
{{- end }}
{{- end }}
{{- if not (or .Values.datasource.dsn .Values.datasource.existingSecret) }}

⚠  No `datasource.dsn` or `datasource.existingSecret` is configured. The
   harness will boot with the datasource disabled — `/health` returns 200
   but no data tools are registered. Set one of:
     * `--set datasource.dsn=postgres://...` (chart creates a Secret)
     * `--set datasource.existingSecret=<name-of-existing-secret>` (production)
{{- end }}
{{- if not (or .Values.anthropic.existingSecret .Values.anthropic.apiKey) }}

⚠  No Anthropic API key is configured. Every default model (agents +
   intent router) is claude-*, so auto-mode requests will fail until you
   set `anthropic.existingSecret` (production) or `anthropic.apiKey` (dev).
{{- end }}
