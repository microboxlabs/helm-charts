MIOT Calendar Chart

A Helm chart for deploying MIOT Calendar - a calendar booking microservice for resource scheduling built with Quarkus.

Overview

MIOT Calendar provides a robust, database-first calendar solution for planning and scheduling resources. It supports:

  • Multiple calendars with configurable time zones
  • Time windows defining operating hours and slot durations
  • Slots with capacity management
  • Bookings for generic resources with JSONB data support
  • Quarkus native and JVM image variants

Prerequisites

  • Kubernetes 1.19+
  • Helm 3.0+
  • PostgreSQL database (external)

Installation

Add the Helm repository

helm repo add mbl-charts https://microboxlabs.github.io/helm-charts
helm repo update

Install with default configuration

helm install miot-calendar mbl-charts/miot-calendar

Install with custom values

helm install miot-calendar mbl-charts/miot-calendar -f values.yaml

Example Configurations

Basic Deployment

replicaCount: 2
 
image:
  repository: ghcr.io/microboxlabs/miot-calendar
  tag: "0.1.0-jvm"
 
postgresql:
  external:
    enabled: true
    host: "postgresql.database.svc.cluster.local"
    database: "miot_calendar"
    schema: "miot_calendar"
    existingSecret: "postgresql-credentials"
    existingSecretUsernameKey: "username"
    existingSecretPasswordKey: "password"
 
resources:
  requests:
    cpu: 100m
    memory: 256Mi
  limits:
    cpu: 500m
    memory: 512Mi

Using Native Image

image:
  repository: ghcr.io/microboxlabs/miot-calendar
  tag: "0.1.0-native"
 
# Native images have faster startup and lower memory footprint
resources:
  requests:
    cpu: 50m
    memory: 64Mi
  limits:
    cpu: 200m
    memory: 128Mi
 
# Native images start much faster
livenessProbe:
  initialDelaySeconds: 2
readinessProbe:
  initialDelaySeconds: 1

With Ingress and TLS

ingress:
  enabled: true
  className: nginx
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
    nginx.ingress.kubernetes.io/proxy-body-size: "10m"
  hosts:
    - host: calendar.example.com
      paths:
        - path: /
          pathType: Prefix
  tls:
    - secretName: calendar-tls
      hosts:
        - calendar.example.com

Troubleshooting

Pod fails to start with database connection error

  1. Verify the PostgreSQL service is running and accessible
  2. Check the database credentials in the secret
  3. Ensure the database miot_calendar exists
kubectl logs -l app.kubernetes.io/name=miot-calendar

Health checks failing

  1. Check if Flyway migrations completed successfully
  2. Verify database connectivity
  3. Review application logs for startup errors
kubectl exec -it <pod-name> -- curl localhost:8083/q/health

Metrics not appearing in Prometheus

  1. Verify the ServiceMonitor is created: kubectl get servicemonitor
  2. Check that the ServiceMonitor labels match your Prometheus selector
  3. Verify the metrics endpoint is accessible: curl <pod-ip>:8083/q/metrics
