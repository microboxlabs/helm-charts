miot-app Chart

A Helm chart for deploying the main ModularIoT application - a Next.js application with authentication, maps, and IoT management capabilities.

Overview

The miot-app chart deploys:

  • Next.js application with server-side rendering
  • NextAuth.js authentication (Google OAuth, Auth0, etc.)
  • Map integrations (Mapbox, Google Maps)
  • IoT device management dashboard

Prerequisites

  • Kubernetes 1.19+
  • Helm 3.0+

Installation

Standalone

helm install miot-app microboxlabs/miot-app \
  --namespace modulariot \
  --create-namespace

As part of umbrella chart

helm install modulariot microboxlabs/modulariot \
  --namespace modulariot \
  --set miot-app.enabled=true

Authentication Setup

Generate Auth Secret

openssl rand -base64 32

Using Values (Google OAuth)

auth:
  secret: "your-generated-secret"
  providers:
    google:
      enabled: true
      clientId: "your-client-id.apps.googleusercontent.com"
      clientSecret: "your-client-secret"

Using Values (Auth0)

Auth0 acts as an identity broker for social logins (Google, GitHub, etc.). Configure the social connections in your Auth0 dashboard, then provide the Auth0 credentials here:

auth:
  secret: "your-generated-secret"
  authProviders: "google,github,credentials"
  providers:
    auth0:
      enabled: true
      clientId: "your-auth0-client-id"
      clientSecret: "your-auth0-client-secret"
      issuer: "https://auth0.microboxlabs.com"
      audience: "https://users.microboxlabs.com/v1"

Using Existing Secret (Google)

Create the secret:

kubectl create secret generic miot-auth \
  --from-literal=auth-secret="your-secret" \
  --from-literal=google-client-id="your-id" \
  --from-literal=google-client-secret="your-secret" \
  -n modulariot

Reference it:

auth:
  existingSecret: miot-auth
  providers:
    google:
      enabled: true

Using Existing Secret (Auth0)

Create the secret:

kubectl create secret generic miot-auth0 \
  --from-literal=auth0-client-id="your-auth0-id" \
  --from-literal=auth0-client-secret="your-auth0-secret" \
  -n modulariot

Reference it:

auth:
  authProviders: "google,github,credentials"
  providers:
    auth0:
      existingSecret: miot-auth0
      issuer: "https://auth0.microboxlabs.com"
      audience: "https://users.microboxlabs.com/v1"

You can also customize the secret key names if your secret uses different keys:

auth:
  providers:
    auth0:
      existingSecret: my-custom-secret
      existingSecretClientIdKey: "my-id-key"
      existingSecretClientSecretKey: "my-secret-key"
      issuer: "https://auth0.microboxlabs.com"

Example Configurations

Development

replicaCount: 1
 
image:
  tag: "latest"
 
auth:
  secret: "dev-secret-change-in-production"

With APISIX Route

Uses an ApisixRoute CRD instead of a standard Ingress resource. Requires the APISIX Ingress Controller  with a GatewayProxy configured.

ingress:
  enabled: false
 
apisixRoute:
  enabled: true
  ingressClassName: apisix
  hosts:
    - host: app.modulariot.example.com
      paths:
        - /app
        - /app/*
  plugins:
    - name: redirect
      enable: true
      config:
        http_to_https: true
    - name: cors
      enable: true

Production

replicaCount: 3
 
image:
  tag: "v1.0.0"
 
resources:
  limits:
    cpu: 1000m
    memory: 1Gi
  requests:
    cpu: 250m
    memory: 512Mi
 
autoscaling:
  enabled: true
  minReplicas: 3
  maxReplicas: 10
 
ingress:
  enabled: true
  className: nginx
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
  hosts:
    - host: app.modulariot.com
      paths:
        - path: /
          pathType: Prefix
  tls:
    - secretName: app-tls
      hosts:
        - app.modulariot.com
 
auth:
  existingSecret: miot-auth-production
  providers:
    google:
      enabled: true
 
env:
  - name: NEXTAUTH_URL
    value: "https://app.modulariot.com"
