miot-dashboard-server Chart

Deploys @microboxlabs/miot-dashboard-server: persistence, identity and tenancy for embeddable dashboards, addressed as /tenants/{tenantId}/scopes/{scopeId}/dashboards.

Prerequisites

  • Kubernetes 1.20+ — the chart sets fsGroupChangePolicy, which 1.19 silently drops
  • Helm 3.0+
  • An identity provider that issues the bearer tokens callers will present
  • A service that answers tenant entitlement and scope membership, over https

Installation

Both commands below carry the whole minimum. A shorter one installs a server that either exits at startup or refuses every request — see the next section.

Standalone

helm install dashboards microboxlabs/miot-dashboard-server \
  --namespace modulariot \
  --create-namespace \
  --set auth.jwt.issuer=https://issuer.example/ \
  --set 'auth.jwt.audience=your-api-audience' \
  --set auth.jwt.jwksUrl=https://issuer.example/.well-known/jwks.json \
  --set 'tenants.url=https://host.example/people/{userId}/tenants/{tenantId}' \
  --set 'scopes.url=https://host.example/people/{userId}/scopes/{scopeId}'

As part of the umbrella chart

The umbrella defaults it to disabled, and enabling it alone is not enough:

helm install modulariot microboxlabs/modulariot \
  --namespace modulariot \
  --create-namespace \
  --set miot-dashboard-server.enabled=true \
  --set miot-dashboard-server.auth.jwt.issuer=https://issuer.example/ \
  --set 'miot-dashboard-server.auth.jwt.audience=your-api-audience' \
  --set miot-dashboard-server.auth.jwt.jwksUrl=https://issuer.example/.well-known/jwks.json \
  --set 'miot-dashboard-server.tenants.url=https://host.example/people/{userId}/tenants/{tenantId}' \
  --set 'miot-dashboard-server.scopes.url=https://host.example/people/{userId}/scopes/{scopeId}'

Two things it refuses to do

Start without an identity providerThe image binds 0.0.0.0, and unverified header identity is only accepted on loopback. With no auth.jwt.* the pod exits at startup instead of listening.
Ask an authority over plain httptenants.url and scopes.url decide who gets in, so they must be https (loopback excepted). A redirect is refused rather than followed.

With neither authority URL set, both fall back to the seed file — and with no seed that is a 403 on every request.

Exactly one key source. The algorithm follows from which one it is, so “accept either” cannot be configured — that is the algorithm-confusion attack.

The ticket scheme is supported by the server but not modelled here; reach it through extraEnv.

Authorization

tenants and scopes take the same keys.

ParameterDescriptionDefault
.urlEndpoint, over {userId} {tenantId} {scopeId}""
.methodGET, or POST to ask in a JSON bodyserver default
.serviceHeader / .serviceValueThis server’s own credential for asking about other people""
.existingSecret / .existingSecretKeyThat credential by Secret reference""
.cacheSeconds / .negativeCacheSecondsHow long an answer is reusedserver defaults
.timeoutMsBefore the lookup gives upserver default
tenants.entitledPathDotted path to a boolean, for a host that answers 200 either way""
scopes.rolePathDotted path to the role in the answerserver default
scopes.roleMap<host role>=<role> pairs""

A GET tenant URL must contain both {userId} and {tenantId}, and a GET scope URL both {userId} and {scopeId} — otherwise every caller asks the same question and one yes answers for all of them.

Roles are Coordinator, Editor, Contributor and Consumer. Without a roleMap the host’s answer must already be one of them.

Probes

PathAnswers
/livez, /healthliveness
/readyzreadiness

None reaches the store. The store is proved at startup instead: migrations run before the listener opens, so a server that cannot reach its database exits rather than listening.

Example: membership from Alfresco

auth:
  jwt:
    issuer: https://auth.example/
    audience: your-api-audience
    jwksUrl: https://auth.example/.well-known/jwks.json
    claims:
      user: email
 
scopes:
  url: https://ecm.example/alfresco/api/-default-/public/alfresco/versions/1/people/{userId}/sites/{scopeId}
  rolePath: entry.role
  roleMap: SiteManager=Coordinator,SiteCollaborator=Editor,SiteContributor=Contributor,SiteConsumer=Consumer
  serviceHeader: authorization
  existingSecret: dashboards-credentials
  existingSecretKey: ecm-authorization
