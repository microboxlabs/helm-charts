miot-harness Chart

A Helm chart for deploying MIOT Harness — the multi-agent FastAPI backend that powers ASK MIOT (miot_harness/api/server.py). Runs in its own cluster (separate from Coordinador) and reaches Coordinador via private connectivity (VNet peering, Private Link, PostgREST, or a kubectl port-forward sidecar for dev).

Overview

The miot-harness chart deploys:

  • FastAPI process on :8000, exposing /health and /runs.
  • Read-only-rootfs container, runs as UID 65534.
  • Three credential channels (Anthropic, OpenAI, Coordinador DSN) with existingSecret-first precedence and a chart-managed Secret fallback for dev.
  • Optional NetworkPolicy (default off) — DNS, public HTTPS, Coordinador CIDR allowlist.
  • Optional tunnel sidecar (default off) — kubectl port-forward inside the Pod for dev environments.
  • Optional ServiceMonitor for Prometheus-Operator scraping of /metrics.
  • Optional PVC for run_store survivability (defaults to emptyDir).

Prerequisites

  • Kubernetes 1.19+
  • Helm 3.0+
  • (Optional) Prometheus Operator if metrics.serviceMonitor.enabled=true.
  • (Optional) A CSI driver / storage class if persistence.enabled=true.
  • (Optional) A CNI that enforces NetworkPolicy if networkPolicy.enabled=true (Calico, Cilium, etc.).

Installation

Standalone

helm install harness microboxlabs/miot-harness \
  --namespace miot-harness \
  --create-namespace

As part of the modulariot umbrella

helm install platform microboxlabs/modulariot \
  --namespace modulariot \
  --set miot-harness.enabled=true

The umbrella defaults miot-harness.enabled: false so existing platform installs don’t suddenly get an agent runtime — opt in per environment.

Example configurations

Local dev — single-tenant, in-cluster sidecar

env: "local"
nexo:
  dsn: "postgres://harness:devpw@127.0.0.1:6434/coordinador"
anthropic:
  apiKey: "sk-ant-dev-xxxxx"   # chart creates a Secret; do NOT commit values.yaml
connectivity:
  tunnel:
    enabled: true
    kubeconfigSecret: "harness-coordinador-kubeconfig"
    args:
      - |
        while true; do
          kubectl port-forward -n coordinador svc/pgbouncer 6434:6432 \
            --address 127.0.0.1 || true
          sleep 5
        done

Staging — existingSecret everywhere, persistence + NetworkPolicy

env: "staging"
replicaCount: 1
 
nexo:
  existingSecret: "harness-nexo-dsn"
anthropic:
  existingSecret: "harness-anthropic-key"
openai:
  existingSecret: "harness-openai-key"
 
persistence:
  enabled: true
  size: 5Gi
  storageClass: managed-csi
 
networkPolicy:
  enabled: true
  coordinador:
    cidrs:
      - 10.10.0.0/16

Production — autoscaled, observability on, hardened

      - 10.0.0.0/16

# Readiness (reflects Nexo state in plan-13 phase 5+)

Troubleshooting

/health reports nexo.enabled: false despite nexo.dsn set

The harness’s freshness gate (miot-harness/integrations/nexo/boot.py) refuses to register Nexo tools if the snapshot is older than MIOT_HARNESS_NEXO_FRESHNESS_REFUSE_MINUTES (default 240). Possible causes:

  1. The Coordinador team hasn’t refreshed the materialized views recently.
  2. Wrong DSN — the harness reaches a stale read replica.
  3. ACL — the harness PG role lacks read on the freshness probe.

Check kubectl logs for Nexo: critical entries; they enumerate the failure mode.

Pod crashes on first /runs invocation with “read-only filesystem”

The container runs with readOnlyRootFilesystem: true. The chart mounts a workspace volume at /app/.miot-workspace; the harness writes run_store JSON there. If you’ve overridden securityContext or volumeMounts in a way that removes the workspace mount, the harness will crash on first write.

Verify with:

kubectl exec -n miot-harness <pod> -- ls -la /app/.miot-workspace
# should be writable by UID 65534

If the directory is missing or read-only, your override has dropped the chart’s workspace volume. Re-check volumes and volumeMounts in your values.

networkPolicy.enabled=true but Pods can’t reach Anthropic / OpenAI

Two common causes:

  1. CNI doesn’t enforce NetworkPolicy. Some Flannel modes ignore policies entirely. Verify with kubectl get pods -n kube-system | grep -E 'cilium|calico|antrea'. If your cluster has no policy-enforcing CNI, the chart’s NetworkPolicy is rendered but does nothing — Pods can reach everything regardless.
  2. Transparent egress proxy. Some clusters intercept HTTPS via an egress proxy with its own allowlist. The chart’s NetworkPolicy permits the destination IP, but the proxy denies the hostname. Audit the egress proxy config.

If the symptom is “Pods can reach Anthropic but not Coordinador”, check networkPolicy.coordinador.cidrs — empty means no Coordinador rule is rendered (intentional fail-closed).

Upgrading

helm upgrade harness microboxlabs/miot-harness \
  --namespace miot-harness \
  -f values.yaml

Rolling restarts: the chart’s Deployment uses default RollingUpdate strategy. The harness’s /health/ready is the readiness gate — pods join traffic only after Nexo bootstraps (or after the chart’s startup grace, whichever applies).

Uninstalling

helm uninstall harness -n miot-harness

Note: the chart-managed credentials Secret and the workspace PVC (if persistence.enabled=true and no existingClaim) are deleted. Back up run_store data first if it matters.
